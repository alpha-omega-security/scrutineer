# Contributing

## Terminology

Prefer plain words and explain specialist terms where they appear, so readers can follow the interface and documentation without opening the [glossary](docs/glossary.md). Expand acronyms on first use. Use the glossary's names consistently and update it when introducing a term readers need to understand.

## Changelog

Don't edit `CHANGELOG.md` in a pull request. Entries are written when a release is cut, not per change, so a PR that touches the changelog just creates a merge conflict for the next one.
