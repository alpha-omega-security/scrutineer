# Changelog

Entries are grouped by release, newest first. Each entry is a summary written for people who fund and direct the work rather than a full commit list; see the git log for that.

## 2026-11-07

- Operators can now set a cost cap for an individual scan. When reported usage reaches the cap, Scrutineer stops the audit and requests a partial report; repair and follow-up checks share the budget. Actual spend can exceed the cap by an in-flight call and report finalization, and the cap does not apply to Codex scans. ([#1245](https://github.com/alpha-omega-security/scrutineer/pull/1245), [@abhinavgautam01](https://github.com/abhinavgautam01); [#1258](https://github.com/alpha-omega-security/scrutineer/pull/1258), [@andrew](https://github.com/andrew))
- Findings now retain each scan's reported severity and evidence, including observations from findings later merged as duplicates. A duplicate with better evidence can also supply the main finding's report while it is still at an early stage, with the changes recorded in its history. ([#1270](https://github.com/alpha-omega-security/scrutineer/pull/1270) [#1311](https://github.com/alpha-omega-security/scrutineer/pull/1311), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Findings can now be filtered by their subproject path, so analysts can separate results for different packages in a shared repository. ([#1253](https://github.com/alpha-omega-security/scrutineer/pull/1253), [@matthew6s](https://github.com/matthew6s))
- Findings across multiple repositories can now be exported together in Static Analysis Results Interchange Format (SARIF), with filters for incremental exports. Exports are limited to 10,000 findings per request; larger selections need narrower filters or the streaming JSONL format. ([#1266](https://github.com/alpha-omega-security/scrutineer/pull/1266), [@mcc0nnell](https://github.com/mcc0nnell))
- Reporting exports now include total cost and token usage for the reporting period, and merged reports add these totals across installations. ([#1312](https://github.com/alpha-omega-security/scrutineer/pull/1312), [@abhinavgautam01](https://github.com/abhinavgautam01))
- History audits now request the full Git history and record partial coverage when the clone or analysis is incomplete. The global `-clone full` option is also honoured for individual audit runs. ([#1241](https://github.com/alpha-omega-security/scrutineer/pull/1241), [@abhinavgautam01](https://github.com/abhinavgautam01); [#1268](https://github.com/alpha-omega-security/scrutineer/pull/1268), [@mcc0nnell](https://github.com/mcc0nnell))
- Scan containers can now use configured package repositories or caching proxies for npm, Python, Go, Dart and Hex dependencies. Hardened deployments still require explicit network access for each repository host and port. ([#1287](https://github.com/alpha-omega-security/scrutineer/pull/1287), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Threat-model and verification scans now receive maintainer-provided threat models and Dockerfiles from the OSS Scanner registry, giving those scans the same project context as other audits. ([#1295](https://github.com/alpha-omega-security/scrutineer/pull/1295), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Audits now require source evidence before claiming that a dependency lacks a limit or has an unsafe default. Claims that cannot be checked against the dependency's implementation are recorded as unresolved assumptions. Betterleaks detections in test fixtures, examples and rule files are also rated Low unless the scanner reports a valid credential. ([#1300](https://github.com/alpha-omega-security/scrutineer/pull/1300) [#1301](https://github.com/alpha-omega-security/scrutineer/pull/1301), [@andrew](https://github.com/andrew))
- The finding page now groups evidence and workflow details into tabs beneath the finding's status and key facts. Repository summaries count every open finding by severity, and findings on the repository page link directly to the code browser. ([#1355](https://github.com/alpha-omega-security/scrutineer/pull/1355) [#1359](https://github.com/alpha-omega-security/scrutineer/pull/1359) [#1362](https://github.com/alpha-omega-security/scrutineer/pull/1362) [#1367](https://github.com/alpha-omega-security/scrutineer/pull/1367), [@alexandre-daubois](https://github.com/alexandre-daubois); [#1262](https://github.com/alpha-omega-security/scrutineer/pull/1262), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Navigation now groups sidebar links and follows the repository and finding hierarchy in breadcrumbs. Repository controls separate scan actions from the More menu, and model-tier settings are saved together. Severity colours are distinct from finding statuses, with layout fixes for long paths and narrow screens. ([#1354](https://github.com/alpha-omega-security/scrutineer/pull/1354) [#1358](https://github.com/alpha-omega-security/scrutineer/pull/1358) [#1361](https://github.com/alpha-omega-security/scrutineer/pull/1361) [#1364](https://github.com/alpha-omega-security/scrutineer/pull/1364) [#1368](https://github.com/alpha-omega-security/scrutineer/pull/1368) [#1370](https://github.com/alpha-omega-security/scrutineer/pull/1370) [#1372](https://github.com/alpha-omega-security/scrutineer/pull/1372), [@alexandre-daubois](https://github.com/alexandre-daubois))
- Codex scans can now select a cyber access program through `codex.cyber_access_program`. Codex commands also preserve the runner image's configured tool paths, fixing failures to find installed toolchains. ([#1374](https://github.com/alpha-omega-security/scrutineer/pull/1374), [@walterhpearce](https://github.com/walterhpearce); [#1383](https://github.com/alpha-omega-security/scrutineer/pull/1383), [@andrew](https://github.com/andrew); [#1385](https://github.com/alpha-omega-security/scrutineer/pull/1385), [@charlie-morrison](https://github.com/charlie-morrison))
- Fixed interrupted scans counting findings they had not reached as missed, which could eventually reject an open finding. Scans stopped by a cost cap or turn limit now leave those missed counts unchanged. ([#1343](https://github.com/alpha-omega-security/scrutineer/pull/1343), [@andrew](https://github.com/andrew))
- Scan credentials can no longer write suggested fixes directly through the finding API, preventing scan output from bypassing the host's patch applicability check. ([#1341](https://github.com/alpha-omega-security/scrutineer/pull/1341), [@andrew](https://github.com/andrew))
- SQLite backup files now have owner-only permissions before any data is written, closing a window in which other local users could read a new snapshot. Backup documentation now covers PostgreSQL and recovery of saved scan sessions. ([#1330](https://github.com/alpha-omega-security/scrutineer/pull/1330) [#1261](https://github.com/alpha-omega-security/scrutineer/pull/1261), [@andrew](https://github.com/andrew))
- Source reads now reject special files without blocking, code highlighting is limited to the displayed lines, and finding-history checks treat filenames literally and bound their output. Reproduction reports also have a limit on code blocks, reducing the resources hostile scan output can consume on the host. ([#1257](https://github.com/alpha-omega-security/scrutineer/pull/1257) [#1259](https://github.com/alpha-omega-security/scrutineer/pull/1259) [#1342](https://github.com/alpha-omega-security/scrutineer/pull/1342) [#1344](https://github.com/alpha-omega-security/scrutineer/pull/1344), [@andrew](https://github.com/andrew))
- Fixed carriage returns in streamed transcript text being interpreted as event fields by the browser. ([#1327](https://github.com/alpha-omega-security/scrutineer/pull/1327), [@andrew](https://github.com/andrew))
- Large software bills of materials now save packages in batches to avoid SQLite parameter limits and resolve package repositories through bulk lookups. Scan lists also avoid loading unused report data. ([#1276](https://github.com/alpha-omega-security/scrutineer/pull/1276) [#1279](https://github.com/alpha-omega-security/scrutineer/pull/1279) [#1260](https://github.com/alpha-omega-security/scrutineer/pull/1260), [@andrew](https://github.com/andrew))
- Runner image builds now time out with build logs when a step stalls, and toolchain downloads retry failed requests. Changes to Ruby native-extension memory-checking suppressions now rebuild the image. ([#1278](https://github.com/alpha-omega-security/scrutineer/pull/1278) [#1293](https://github.com/alpha-omega-security/scrutineer/pull/1293) [#1337](https://github.com/alpha-omega-security/scrutineer/pull/1337), [@andrew](https://github.com/andrew))
- Fixed follow-up audits discarding their report when a skipped directory was written with a trailing slash. ([#1271](https://github.com/alpha-omega-security/scrutineer/pull/1271), [@miketheman](https://github.com/miketheman))

## 2026-10-24

- Scrutineer now refuses to start with `--hardened` on Docker Engine, because a scan on its internal network could reach host services listening on all interfaces without going through the egress proxy. Docker Engine deployments should switch to `--hardened-runtime-only`, or move to Docker Desktop or podman for full network isolation. Scan containers are also removed when a run ends. ([#1203](https://github.com/alpha-omega-security/scrutineer/pull/1203), [@alexandre-daubois](https://github.com/alexandre-daubois))
- Operator sign-in can now be recovered after a restart: every start logs the sign-in link and the full path of the token file, and instances sharing a host no longer overwrite each other's sign-in. Browsers signed in before upgrading need to sign in again through the logged link. ([#1172](https://github.com/alpha-omega-security/scrutineer/pull/1172), [@andrew](https://github.com/andrew))
- New installations can use PostgreSQL instead of SQLite, and existing SQLite installations can be copied into an empty PostgreSQL database with a migration script. ([#1076](https://github.com/alpha-omega-security/scrutineer/pull/1076) [#1079](https://github.com/alpha-omega-security/scrutineer/pull/1079), [@andrew](https://github.com/andrew))
- Scrutineer can now take part in OpenSSF OSS-CRS campaigns as an auditing system, running a one-off audit of a source directory with the new `scrutineer audit` command and submitting its findings as bug candidates. The auditor can use a Claude subscription token, which calls Anthropic directly instead of the campaign's model proxy. Repository findings can also be exported as SARIF for use in other security tooling. ([#1210](https://github.com/alpha-omega-security/scrutineer/pull/1210) [#1211](https://github.com/alpha-omega-security/scrutineer/pull/1211), [@abhinavgautam01](https://github.com/abhinavgautam01); [#1224](https://github.com/alpha-omega-security/scrutineer/pull/1224), [@andrew](https://github.com/andrew); [#1200](https://github.com/alpha-omega-security/scrutineer/pull/1200), [@alexandre-daubois](https://github.com/alexandre-daubois))
- Vulnerability reports submitted from elsewhere can now be investigated without a full scan. The investigation assesses each claim in the report against the code at a given revision, records any findings, and keeps the original report with the result. ([#1205](https://github.com/alpha-omega-security/scrutineer/pull/1205), [@andrew](https://github.com/andrew))
- Reviewed findings can now be submitted to Akrites, with an editable report, duplicate submissions prevented, and intake status tracked on the submission page. ([#1126](https://github.com/alpha-omega-security/scrutineer/pull/1126), [@andrew](https://github.com/andrew))
- Code that parses untrusted file formats, such as archives, images, documents and serialization formats, now gets a dedicated audit, as do build systems and developer tools, which are checked for what an untrusted checkout can make them run. ([#1216](https://github.com/alpha-omega-security/scrutineer/pull/1216) [#1199](https://github.com/alpha-omega-security/scrutineer/pull/1199), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Operators can now grant a single scan extra network access under hardened isolation by choosing a named policy from the config when starting it, without widening access for every run of that audit. Retries keep the chosen policy. ([#1215](https://github.com/alpha-omega-security/scrutineer/pull/1215), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Reproduction files written during a scan are now kept with their finding, so disclosure bundles and later verification use the original files with their names intact. Reports with ambiguous or unsafe reproduction files are rejected and sent for repair. ([#1122](https://github.com/alpha-omega-security/scrutineer/pull/1122) [#1123](https://github.com/alpha-omega-security/scrutineer/pull/1123), [@andrew](https://github.com/andrew))
- An analyst's false-positive decision now becomes a standing exclusion once later revalidation or changed-code audits have confirmed it at three separate commits. Any failure in that process removes an exclusion rather than adding one. ([#1134](https://github.com/alpha-omega-security/scrutineer/pull/1134) [#1180](https://github.com/alpha-omega-security/scrutineer/pull/1180), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Disclosure drafts now follow a project's custom GitHub vulnerability report form when it defines one, so reports filed through private vulnerability reporting are not rejected for missing the form's sections. ([#1140](https://github.com/alpha-omega-security/scrutineer/pull/1140), [@alexandre-daubois](https://github.com/alexandre-daubois))
- Project discovery and Scan all now include a package at the repository root alongside workspace subprojects, such as a Composer package next to JavaScript workspaces. Existing repositories need project discovery rerun to pick it up. ([#1186](https://github.com/alpha-omega-security/scrutineer/pull/1186), [@andrew](https://github.com/andrew))
- Focus-area audits now keep the full source tree so code can be built and callers traced, and pick a runner from the area's own language, so a JavaScript area in a mixed PHP repository gets the Node toolchain. JavaScript packages without a lockfile now also get the Node runner. ([#1164](https://github.com/alpha-omega-security/scrutineer/pull/1164), [@abhinavgautam01](https://github.com/abhinavgautam01); [#1183](https://github.com/alpha-omega-security/scrutineer/pull/1183) [#1184](https://github.com/alpha-omega-security/scrutineer/pull/1184), [@andrew](https://github.com/andrew))
- Scan details now show the subpath, focus area and runner profile, and repository scan lists show the subpath, so scans of different workspace packages can be told apart. ([#1185](https://github.com/alpha-omega-security/scrutineer/pull/1185), [@andrew](https://github.com/andrew))
- The operator API can now fetch a single repository or finding by ID, and finding exports include every recorded field, including CVSS v4, fix suggestions and release data. The instance-wide findings export can be limited to curated findings, one repository, or findings created or updated since a given time, so clients can fetch incremental exports. ([#1193](https://github.com/alpha-omega-security/scrutineer/pull/1193) [#1178](https://github.com/alpha-omega-security/scrutineer/pull/1178) [#1231](https://github.com/alpha-omega-security/scrutineer/pull/1231), [@abhinavgautam01](https://github.com/abhinavgautam01))
- A glossary now defines the terms used across scans, findings and disclosure, and the interface and docs use them consistently. ([#1136](https://github.com/alpha-omega-security/scrutineer/pull/1136), [@andrew](https://github.com/andrew); [#1206](https://github.com/alpha-omega-security/scrutineer/pull/1206), [@alexandre-daubois](https://github.com/alexandre-daubois))
- Releases and the Go runner profile now use Go 1.27.3, and the Go networking and crypto libraries are updated, picking up upstream security fixes for certificate validation, HTTP/2 and SSH. ([#1230](https://github.com/alpha-omega-security/scrutineer/pull/1230), [@andrew](https://github.com/andrew))
- Fixed accessibility issues found in an audit of the web interface, including navigation being unreachable on narrow screens and keyboard focus in filter menus. ([#1219](https://github.com/alpha-omega-security/scrutineer/pull/1219), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Fixed Claude scan costs being counted more than once when a session reported the same running total again, such as after a retry, pause or resumed session. Historical costs are unchanged. ([#1171](https://github.com/alpha-omega-security/scrutineer/pull/1171), [@andrew](https://github.com/andrew))
- Fixed the Python C-extension runner failing to build on recent Apple Silicon hosts, which left those projects scanned without memory-error detection. ([#1202](https://github.com/alpha-omega-security/scrutineer/pull/1202), [@mechko](https://github.com/mechko))
- Fixed the code browser showing "No local clone yet" for every file in a local repository; it now reads files from the repository's own history. ([#1179](https://github.com/alpha-omega-security/scrutineer/pull/1179), [@abhinavgautam01](https://github.com/abhinavgautam01))

## 2026-10-10

- The dashboard and operator API now require an operator token, preventing unauthenticated access to scan controls and findings. After upgrading, sign in through the link logged when the token is first created; scripts calling `/api/v1` must send the token stored in the data directory's `operator-token` file as a bearer token. ([#1142](https://github.com/alpha-omega-security/scrutineer/pull/1142), [@alexandre-daubois](https://github.com/alexandre-daubois))
- Web applications and APIs now get a dedicated audit when their source code shows implemented application behaviour, checking sessions, browser access boundaries, uploads and business workflows. Related access-control and injection audits are added where the code supports them. ([#1101](https://github.com/alpha-omega-security/scrutineer/pull/1101), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Device firmware now gets a dedicated audit covering updates, boot security, provisioning, credentials and device communications. Guarantees that need hardware or deployment evidence are recorded as unresolved assumptions rather than reported as proven flaws. ([#1130](https://github.com/alpha-omega-security/scrutineer/pull/1130), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Claude scans using an Anthropic API key can now keep that key on the host with `-model-proxy`. Each container receives a token limited to supported model requests and revoked when its scan ends, reducing the risk of a hostile repository stealing a reusable credential. ([#1103](https://github.com/alpha-omega-security/scrutineer/pull/1103), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Operators can now grant individual audits access to named services on specified ports under hardened isolation, such as allowing dependency metadata lookups without widening network access for every scan. Docker Desktop and rootless Podman deployments need an updated runner image to use these policies; pull or rebuild it after upgrading. ([#1114](https://github.com/alpha-omega-security/scrutineer/pull/1114), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Completed audit batches on a repository's default branch can now produce notes on tool failures, missing dependencies and reproduction entry points for later audits. Each note cites the original scan log and is kept with the threat model; later audits must recheck it against current code and tools. ([#1090](https://github.com/alpha-omega-security/scrutineer/pull/1090), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Reporting exports from separate installations can now be merged into one report, combining counts and weighting averages by the number of scans. The merge tool checks that export fields match and refuses mixed reporting periods unless explicitly allowed. ([#1129](https://github.com/alpha-omega-security/scrutineer/pull/1129), [@dkw-oss](https://github.com/dkw-oss))
- The audit log now records operator requests to retry, resume, pause and cancel scans, plus disclosure requests, draft edits, communications and changes to disclosure contacts. Events are saved together with the changes they describe, while draft and communication text are kept out of event payloads. ([#1094](https://github.com/alpha-omega-security/scrutineer/pull/1094) [#1137](https://github.com/alpha-omega-security/scrutineer/pull/1137), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Codex's model list now includes GPT-6 Sol and GPT-6 Luna, with cost estimates for both, and removes GPT-5.2 from the built-in choices to match the bundled CLI's supported models. ([#1096](https://github.com/alpha-omega-security/scrutineer/pull/1096), [@p-linnane](https://github.com/p-linnane); [#1111](https://github.com/alpha-omega-security/scrutineer/pull/1111), [@andrew](https://github.com/andrew))
- Settings now shows the source commit and build or commit date, with modified checkouts identified, so operators can include the exact build in bug reports. ([#1121](https://github.com/alpha-omega-security/scrutineer/pull/1121), [@andrew](https://github.com/andrew))
- Fixed Ruby projects defined by a gemspec or Hoe selecting the wrong runner; they now use the Ruby toolchain, including when Ruby is a secondary language. ([#1125](https://github.com/alpha-omega-security/scrutineer/pull/1125), [@andrew](https://github.com/andrew))

## 2026-09-26

- Selected audit runs now include an independent search for flaws outside the planned audit, either examining a randomly chosen source directory or challenging an area the threat model excluded. Explicit operator exclusions still apply. ([#1004](https://github.com/alpha-omega-security/scrutineer/pull/1004), [@abhinavgautam01](https://github.com/abhinavgautam01); [#1054](https://github.com/alpha-omega-security/scrutineer/pull/1054), [@andrew](https://github.com/andrew))
- Package manager clients, registries and proxies now get a dedicated audit when detected, checking their implementation against a bundled package-manager threat model. ([#1077](https://github.com/alpha-omega-security/scrutineer/pull/1077), [@andrew](https://github.com/andrew))
- Repositories can now be assessed against the OpenSSF Baseline, with results for each control and the attained level shown on a new Compliance tab. ([#1055](https://github.com/alpha-omega-security/scrutineer/pull/1055), [@alexandre-daubois](https://github.com/alexandre-daubois))
- Scans now check the available Git history for leaked secrets using Betterleaks, with raw secret values removed before findings are written. ([#1052](https://github.com/alpha-omega-security/scrutineer/pull/1052), [@andrew](https://github.com/andrew))
- Analysts can now explain why a finding was rejected, distinguishing false positives from already-fixed or otherwise non-actionable findings. Relevant false-positive decisions are passed to later revalidation and changed-code audits, which must check the reason against current code before applying it. ([#1065](https://github.com/alpha-omega-security/scrutineer/pull/1065), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Verification can now be rerun with operator feedback, such as a missed entry point or an incorrect reproduction assumption, and that guidance stays with the run and its verification history. ([#1011](https://github.com/alpha-omega-security/scrutineer/pull/1011), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Each finding now records which model first produced it, including in exports and sharing bundles, and the reporting page breaks down scans, findings and cost by model. Existing findings are attributed to their producing scan's model on upgrade. ([#1041](https://github.com/alpha-omega-security/scrutineer/pull/1041), [@dkw-oss](https://github.com/dkw-oss))
- Scrutineer now builds and runs on Windows hosts, with a packaged Windows binary and scans running under Docker Desktop. Cancelling a scan also terminates its child processes. ([#995](https://github.com/alpha-omega-security/scrutineer/pull/995), [@alexandre-daubois](https://github.com/alexandre-daubois); [#1089](https://github.com/alpha-omega-security/scrutineer/pull/1089), [@andrew](https://github.com/andrew))
- Kotlin projects now have a dedicated runner profile with compiler tools and audit guidance for Kotlin code. ([#1056](https://github.com/alpha-omega-security/scrutineer/pull/1056), [@andrew](https://github.com/andrew))
- Audits can now declare the tools and runtime features they need, so missing requirements stop a run before model work begins or explicitly limit its reported coverage. Operators can also enable cached live checks of the selected model backend to catch request failures before an audit starts. ([#1033](https://github.com/alpha-omega-security/scrutineer/pull/1033) [#1081](https://github.com/alpha-omega-security/scrutineer/pull/1081), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Operators can now choose to pause active and queued model scans when Claude reports paid subscription overage, preserving work for resumption after the reported reset or operator action. ([#1042](https://github.com/alpha-omega-security/scrutineer/pull/1042), [@abhinavgautam01](https://github.com/abhinavgautam01))
- The audit log now records changes to finding status, severity and labels, plus repository additions and deletions. Each event is saved together with the change it describes, and deleting a repository preserves its earlier audit history. ([#1064](https://github.com/alpha-omega-security/scrutineer/pull/1064) [#1086](https://github.com/alpha-omega-security/scrutineer/pull/1086), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Scan lists now show each audit's focus area, with a link to the other scans in its batch and retries limited to that batch when filtered. ([#1023](https://github.com/alpha-omega-security/scrutineer/pull/1023), [@edorian](https://github.com/edorian))
- Scan exports can now be filtered by repository, scan kind and creation time, so monitoring tools can fetch only the runs they need. ([#1039](https://github.com/alpha-omega-security/scrutineer/pull/1039), [@p-linnane](https://github.com/p-linnane))
- Finding workflow buttons now distinguish actions that start a model job from actions that record an analyst's decision. ([#1037](https://github.com/alpha-omega-security/scrutineer/pull/1037), [@p-linnane](https://github.com/p-linnane))
- Fixed advisory exports and disclosure bundles listing unrelated packages from the same monorepo; package identities are now limited to the finding's attributed subproject. ([#1067](https://github.com/alpha-omega-security/scrutineer/pull/1067), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Fixed repository deletion being blocked by paused scans, and made deletion failures visible on the page. ([#1024](https://github.com/alpha-omega-security/scrutineer/pull/1024), [@edorian](https://github.com/edorian))

## 2026-05-18

- Each repository now gets a written threat model describing its trust boundaries and attack surface, which later audits work from. ([#188](https://github.com/alpha-omega-security/scrutineer/pull/188), [@andrew](https://github.com/andrew))
- Exposure analysis: for a confirmed vulnerability, work out which downstream projects that depend on the affected code are actually reachable by it. ([#200](https://github.com/alpha-omega-security/scrutineer/pull/200), [@alexandre-daubois](https://github.com/alexandre-daubois))
- Findings can be filed directly with maintainers through GitHub's private vulnerability reporting. ([#184](https://github.com/alpha-omega-security/scrutineer/pull/184), [@andrew](https://github.com/andrew))
- Findings export in the CSAF/VEX format used by downstream vulnerability tooling. ([#98](https://github.com/alpha-omega-security/scrutineer/pull/98), [@alexandre-daubois](https://github.com/alexandre-daubois))
- Audits now cover authorisation flaws (accessing another user's records) and prompt-injection risks in code that calls AI models. ([#196](https://github.com/alpha-omega-security/scrutineer/pull/196), [@N0tre3l](https://github.com/N0tre3l); [#170](https://github.com/alpha-omega-security/scrutineer/pull/170), [@andrew](https://github.com/andrew))
- Findings from other scanners and spreadsheets can be imported and tracked alongside Scrutineer's own. ([#187](https://github.com/alpha-omega-security/scrutineer/pull/187), [@andrew](https://github.com/andrew))

## 2026-05-04

- Project start. A web application and job queue that clone open-source repositories, run AI-driven security audits inside an isolated container, and record what they find.
- Upload a software bill of materials and Scrutineer queues a scan of every dependency it lists. ([#86](https://github.com/alpha-omega-security/scrutineer/pull/86), [@andrew](https://github.com/andrew))
- Each confirmed finding gets a drafted security advisory and a candidate patch. ([#39](https://github.com/alpha-omega-security/scrutineer/pull/39) [#40](https://github.com/alpha-omega-security/scrutineer/pull/40), [@andrew](https://github.com/andrew))
- Individual packages inside a monorepo can be scanned on their own. ([#43](https://github.com/alpha-omega-security/scrutineer/pull/43), [@andrew](https://github.com/andrew))
- Per-scan cost and token usage is recorded and shown on a usage page. ([#79](https://github.com/alpha-omega-security/scrutineer/pull/79), [@andrew](https://github.com/andrew))
- Repositories are matched to their CVE Numbering Authority so disclosures are routed to the right contact. ([#92](https://github.com/alpha-omega-security/scrutineer/pull/92), [@andrew](https://github.com/andrew))
